# Changes.Watch upgrade verdict

A GitHub Action that comments on pull requests with an evidence-backed verdict for every npm dependency change: **install, wait, skip, review or avoid** — with the reason and a link to the evidence.

```
| Package | Change           | Verdict  | Why                                                    |
|---------|------------------|----------|--------------------------------------------------------|
| next    | 16.3.6 → 16.4.2  | 🟢 Safe   | fixes 6 advisories (1 high/critical) · no follow-up hotfix |
| eslint  | 8.57.1 → 9.12.0  | 🔵 Review | Release notes list 3 breaking changes: …               |
| debug   | 4.4.1 → 4.4.2    | 🔴 Avoid  | Malicious code reported (MAL-2025-46974).              |
```

Verdicts come from public evidence — OSV (including the OpenSSF malicious-packages feed), deps.dev, the npm registry, GitHub issues after each release, official release notes — and from developers who vote "worked" / "broke something". See [how verdicts work](https://www.changes.watch/packages/how-verdicts-work).

## Usage

```yaml
# .github/workflows/upgrade-verdict.yml
name: Upgrade verdicts
on:
  pull_request:
    paths: ["package-lock.json"]

permissions:
  contents: read
  pull-requests: write

jobs:
  verdicts:
    runs-on: ubuntu-latest
    steps:
      - uses: ChangesWatch/upgrade-verdict@v1
        # with:
        #   fail-on: avoid   # fail the check on an "avoid" verdict
```

No `actions/checkout` is needed: the Action reads `package-lock.json` at the PR base and head commits through the GitHub API and never executes pull request code. Do not combine it with `pull_request_target` plus a checkout of the PR head.

**Dependabot and Renovate PRs** work with the `permissions` block above. Workflows triggered by Dependabot get a read-only token unless the workflow requests permissions explicitly. **Fork PRs** get a read-only token: the Action then skips the comment and writes the verdicts to the job summary.

## Inputs

| Input | Default | Description |
|---|---|---|
| `github-token` | `${{ github.token }}` | Reads the lockfile and writes one PR comment. |
| `lockfile` | `package-lock.json` | Path to an npm lockfile (v2 or v3). |
| `fail-on` | `none` | `avoid` fails the check when a change gets an avoid verdict. |
| `comment` | `true` | `false` writes only the job summary. |
| `telemetry` | `true` | Sends an anonymous install id; `false` opts out (see Privacy). |
| `api-url` | `https://www.changes.watch` | Verdict API origin. |

Outputs: `changed-count`, `avoid-count`, `comment-url`.

## Privacy

The Action sends only public package names and versions, the client name (`upgrade-verdict/<version>`) and — unless `telemetry: false` — an anonymous install id: a SHA-256 hash of the numeric repository id and a fixed public salt. It never sends repository names, code, file contents or user data. The install id lets Changes.Watch count active installs; it cannot be reversed into a repository name without already knowing the repository id.

## Comment safety

The comment contains only text generated by the Action and links to changes.watch. Maintainer-written text (for example npm deprecation messages) is never copied; Markdown is escaped and @mentions are neutralised.

## Development

```sh
npm ci
npm run check   # typecheck, tests, build into dist/
```

`dist/` is committed; CI fails when it is out of date.
